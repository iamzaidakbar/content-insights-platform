# Content Insights Platform — Acceptance Checklist

Verified 2026-08-11 against the live stack (API `localhost:4000`, web `localhost:5173`, MongoDB/Elasticsearch/Redis via Docker), seeded org **"Meridian Media Intelligence"**. Every row below is backed by an actual run of `e2e/*.spec.ts` performed for this checklist (not a stale summary) plus source-code reading where a rule has no reachable UI/API trigger. Scorecard across both tables: **24 Pass · 1 Fixme (real, confirmed gap) · 5 Not covered** (documented below, each cross-checked by code review).

**Post-audit fix**: Table 2 rule #2 (Snapshot cap) was originally Fixme because `ArticlesPage`'s Save flow had no reachable path to create a Snapshot at all — it used a local, ad-hoc modal with only Name+Group fields, while the properly-built `SavedQueriesModal` (with a real Dynamic/Snapshot picker) sat unwired. Fixed by replacing the ad-hoc modal with `SavedQueriesModal` in `ArticlesPage.tsx`; verified live (Snapshot now selectable, saves successfully, round-trips as type Snapshot via Load) and via the full `e2e` suite (35/35, after updating 5 assertions in `save-load-channels.spec.ts`/`tags-insights-dashboards.spec.ts` that hardcoded the old modal's heading/toast text — the new modal intentionally stays open and switches to its Load tab after a successful save, rather than closing, so the user sees the result immediately). See rule #2's updated row below.

## Test run summary

| Run | Result |
|---|---|
| `E2E_LIVE=1 npx playwright test` (default, 6 workers on this machine) | **27 passed / 3 failed / 5 downstream-skipped** of 35 |
| `E2E_LIVE=1 npx playwright test --workers=1` (serial) | **35/35 "passed"** in Playwright's accounting (34 genuine passes + 1 intentional `test.fail()`) |

All 3 concurrent-run failures were reproduced, root-caused, and confirmed to be **cross-file fixture races, not product defects**: several spec files intentionally drive the *same* seeded account concurrently (e.g. `analyst.compliance@meridian.dev` is used by `login-and-explore.spec.ts`, `save-load-channels.spec.ts`, and `tags-insights-dashboards.spec.ts` at once) and mutate its server-persisted `currentProjectId` mid-run. Under 6-way file-level concurrency, one file occasionally observes a value another file's test just wrote a moment earlier. The one test that hit its 150s timeout (`Insights & Dashboards: ...`) did so waiting on a UI element under heavy shared-stack load and completed normally in 10.6s once run without contention. Re-running with `--workers=1` removes both effects and every test resolves exactly as designed, including the one deliberate `test.fail()` (see workflow #1).

**Recommendation**: use `--workers=1` for a trustworthy signal; the default concurrent run is a fine fast smoke check but will show 2–3 flaky failures purely from these specs' shared-account design, not from the app.

**Dataset hygiene check**: the concurrent run's `Insights & Dashboards: ...` test hit its 150s timeout mid-cleanup (after `Dashboard actions` never became clickable in time), which meant its own `finally`-less cleanup steps never ran and left one disposable dashboard + insight (`E2E — Dash-*` / `E2E — Insight-*`) behind. Found and removed via direct API calls while preparing this checklist; a full post-run audit (saved searches, groups, tags, insights, dashboards, concepts, users, and the affected accounts' `currentProjectId`/role assignments) now matches the original seed exactly. The org's live article total is a few articles higher than the seed script's fixed 240 (news count only, hidden and file_system counts unchanged) — that's the always-on ingest simulator (row 9) genuinely doing its job over the stack's uptime, not drift or leakage.

**Notes**
- **Row 1 gap** — grepped the entire web app: zero references to `GroupDefaultQuery` in `ArticlesPage`, and the admin Data Access modal's own "Default Query" tab admits it outright: *"There is currently no way to look up an existing default from here."* Login also leaves `currentProjectId: null` (verified via `POST /api/auth/login`). The seeded default itself ("All Financial Coverage" for Executive Briefing → Financial Markets Watch) is real and correctly configured server-side — nothing in the shipped UI ever applies it.
- **Row 9** — `apps/api/src/workers/ingest.worker.ts` runs a 30-minute interval timer (`NEWS_SIMULATION_INTERVAL_MS`, started in `index.ts`) that fabricates a handful of plausible NEWS articles per project per day, deduped by `locationHash` (same-day re-run is a no-op). A second path (BullMQ `articleIngestQueue` → `articleIndexQueue`) handles admin-triggered File-System re-extraction (`POST /admin/reindex`). Neither has an on-demand UI/API trigger, and 30 minutes is impractical to await in a test, so this remains **not covered by an e2e test** — but it was incidentally confirmed live while preparing this checklist: the org's visible article total had grown past the seed script's fixed 240 (news count only — hidden and file_system counts were unchanged), consistent with the simulator having fired at least once against this long-running dev process.

## How to run this yourself

```bash
docker compose up -d mongodb elasticsearch redis   # API + web are assumed already running (pnpm dev)

E2E_LIVE=1 npx playwright test --workers=1         # deterministic — recommended
E2E_LIVE=1 npx playwright test                     # default/faster; ~2-3 flaky cross-file failures possible, see "Test run summary"
```

- Web: http://localhost:5173
- API: http://localhost:4000 (health check: `GET /health`)
- Seeded admin login: `admin@meridian.dev` / `ContentInsights!23`

Do **not** re-run the seed script with `SEED_RESET=1` — the current seeded data is exactly what every row above (and every test that creates data) was written to clean up after itself against. Wiping it invalidates this checklist.
